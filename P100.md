# p100-v2 branch layout

Fork of llama.cpp for 2x Tesla P100 (sm_60): one model split over both cards (`-sm tensor`), q4_0 KV cache, MTP speculative decoding.

- Base: `llama_master/master` (ggml-org/llama.cpp)
- Stack: 8 topic commits, ~87 files, ~+25.8k / -0.2k lines
- Docs, OPTLOG, handoff notes, bench tools, SASS generator scripts: separate repo `../p100-lab`

## Design rule

Upstream files carry only small hooks. All real P100 code lives in new files, which never conflict on rebase.

Four hook patterns are used:

| Pattern | How it looks in the upstream file | Used for |
|---|---|---|
| Function hook | `if (ggml_cuda_p100_xxx(...)) { return; }` at the top of an upstream function | norm.cu, fattn.cu |
| Build switch (sm_60 only) | `#if GGML_CUDA_P100_MMVQ` / `GGML_CUDA_P100_FATTN`: P100 copy, else upstream body | mmvq.cu, fattn-tile.cuh, fattn-vec.cuh |
| Full replacement (all builds) | `#include "x-p100.cuh"` + `#ifndef GGML_CUDA_GDN_P100 ... #endif` around the upstream file | gated_delta_net.cu/.cuh |
| Textual include | `#include "x-p100.inc"` / `#include "p100/x.cuh"` at the spot where the code used to be | ggml-cuda.cu, sampling.cpp, common.cpp, llama-kv-cache.cpp, test-backend-ops.cpp |

The sm_60 switch is `__CUDA_ARCH_LIST__ == 600`, so only a pure `-DCMAKE_CUDA_ARCHITECTURES=60` build (build_p100_llama.sh) uses the P100 kernels. Other builds use upstream kernels.

## ggml/src/ggml-cuda: new files (no conflicts)

### Mat-vec (decode, MTP verify)
- `mmvq-p100.cu/.cuh`: full P100 copy of mmvq.cu (staged loads, Pascal geometry, q8_1 activation cache, active columns, column chunks). mmvq.cu forwards here in sm_60 builds.
- `vecdotq-p100.cuh`: P100 vec_dot functions (aligned loads, funnel shift, XMAD).
- `mmvq-f16.cu/.cuh`: fp16 mat-vec for verify widths, fused gate+up+SWIGLU, GDN gate.

### Flash attention
- `fattn-p100.cu/.cuh`: dispatch: compact causal mask (all builds), cuBLAS-GEMM attention, q4_0 decode/verify kernel, alloc-size early-outs.
- `fattn-tile-p100.cuh`, `fattn-vec-p100.cuh`: P100 copies of the tile/vec headers (q4_0 direct in tile, GQA folding in vec). The upstream headers switch to them in sm_60 builds.
- `fattn-gemm.cu/.cuh`: GEMM attention for prefill (fold kernels).
- `fattn-q4p.cuh`: q4_0 few-token attention kernel.
- `fattn-fold-sass.h`: precompiled SASS (generated, see p100-lab tools/sass-gemm).

### Prefill GEMM
- `gemm-fold.cu/.cuh`: fp16-product/fp32-accumulate GEMM, pair fusion, SwiGLU prescale, chunked exchange.
- `gemm-fold-u2-sass.h`: precompiled SASS (generated).

### Norm, GDN, conv, misc fusions
- `norm-p100.cu/.cuh`: RMS norm warp kernel and fused forms (scale, scale2, add+norm+mul, silu gate). Hooked from norm.cu.
- `gated_delta_net-p100.cu/.cuh`: P100 GDN (state gather in place, fused l2 pre-op, cache-row state). Replaces upstream in all builds.
- `gdn-chunked.cu/.cuh`: chunked GDN prefill.
- `ssm-conv-p100.cu/.cuh`: fused single-token CONCAT+CPY+SSM_CONV+SILU.
- `unary-p100.cu/.cuh`: fused ADD+SOFTPLUS+MUL (GDN gate).
- `cpy-batch.cu/.cuh`: batched same-shape copies.
- `p60-moe-gemm.cu/.cuh`: fp16 MoE expert GEMM (off unless `GGML_CUDA_P60_MOE_GEMM=1`).

### ggml-cuda/p100/ (textually included by ggml-cuda.cu, uses its static helpers)
- `try-fuse.cuh`: the fork's fusions, called from 2 hooks in ggml_cuda_try_fuse (pre / post).
- `allreduce-p2p.cuh`: two-GPU P2P all-reduce, chunked exchange.
- `peer-copy-f16.cuh`: peer copy on its own stream, f16-compressed when exact.
- `graphs.cuh`: CUDA graphs on Pascal (`GGML_CUDA_GRAPHS_PRE_VOLTA`).
- `gdn-fusion.cuh`, `gdn-state-gather.cuh`, `topk-moe-staged.cuh`, `mul-mat-cublas-f16.cuh`: helpers.

## Environment variables still read

- Used by the start scripts: `GGML_CUDA_P2P`, `GGML_CUDA_GRAPHS_PRE_VOLTA` (=3), `LLAMA_SPEC_SAMPLE_TEMP`, `LLAMA_SPEC_DRAFT_TOPK`
- Optional: `GGML_CUDA_P60_MOE_GEMM=1` (MoE expert GEMM)
- Upstream with a changed Pascal default: `GGML_CUDA_AR_BF16_THRESHOLD`

All other experiment, debug and tuning knobs were removed. Their default behavior is now fixed (list in p100-lab/ENV-INVENTORY.md).

## Rebase workflow

Step-by-step guide for the maintenance agent: P100-MAINTENANCE.md

- `git config rerere.enabled true` is set: resolved conflicts are replayed automatically.
- `./p100-rebase.sh`: fetch, rebase onto llama_master/master, clean build, test-backend-ops for MUL_MAT, MUL_MAT_ID, FLASH_ATTN_EXT, RMS_NORM, GATED_DELTA_NET, SSM_CONV, CONCAT. Then check speed by hand (Q5_K_M ~50 t/s, Q6_K ~44 t/s).
- Fixes: `git commit --fixup=<topic commit>` then `git rebase -i --autosquash llama_master/master` keeps the stack at 8 commits.
